# 게시글(Articles) API 테스트 시나리오

## 사전 준비
-   테스트용 사용자 계정 2개 생성 (user1, user2)
-   `user1`이 `user2`를 팔로우하는 상태로 설정

## 1. 게시글 생성 (POST /api/articles)
-   **성공 케이스**
    -   `user1`의 토큰으로 로그인하여, 유효한 `title`, `description`, `body`를 포함한 게시글을 생성하고 200 OK와 생성된 게시글 객체를 받는지 확인.
    -   생성된 게시글의 `slug`가 `title`을 기반으로 올바르게 생성되었는지 확인.
    -   생성된 게시글의 `author`가 `user1`의 프로필 정보와 일치하는지 확인.
-   **실패 케이스**
    -   인증 토큰 없이 게시글 생성을 시도하고 401 Unauthorized 에러를 받는지 확인.
    -   `title` 필드가 비어있는 요청으로 게시글 생성을 시도하고 422 Unprocessable Entity 에러를 받는지 확인.

## 2. 게시글 목록 조회 (GET /api/articles)
-   **성공 케이스**
    -   인증 없이 게시글 목록을 조회하고, 최신순으로 정렬된 목록과 `articlesCount`를 받는지 확인.
    -   `limit=5`, `offset=0` 파라미터로 조회하여 5개의 게시글만 반환되는지 확인.
    -   `author={user1의 username}` 파라미터로 조회하여 `user1`이 작성한 게시글만 반환되는지 확인.
    -   (게시글에 태그 기능 추가 후) `tag=test` 파라미터로 조회하여 'test' 태그를 가진 게시글만 반환되는지 확인.
    -   (게시글 좋아요 기능 추가 후) `favorited={user2의 username}` 파라미터로 조회하여 `user2`가 좋아요 한 게시글만 반환되는지 확인.

## 3. 게시글 피드 (GET /api/articles/feed)
-   **성공 케이스**
    -   `user1`의 토큰으로 로그인하여 피드를 조회했을 때, `user2`가 작성한 게시글이 포함되어 있는지 확인.
    -   `user1`이 작성한 게시글은 피드에 포함되지 않는지 확인.
-   **실패 케이스**
    -   인증 토큰 없이 피드 조회를 시도하고 401 Unauthorized 에러를 받는지 확인.

## 4. 단일 게시글 조회 (GET /api/articles/{slug})
-   **성공 케이스**
    -   존재하는 게시글의 `slug`로 조회하여, 해당 게시글의 전체 정보가 반환되는지 확인.
-   **실패 케이스**
    -   존재하지 않는 `slug`로 조회를 시도하고 404 Not Found 에러를 받는지 확인.

## 5. 게시글 수정 (PUT /api/articles/{slug})
-   **성공 케이스**
    -   `user1`이 자신이 작성한 게시글의 `body`를 수정하고, 200 OK와 수정된 게시글 객체를 받는지 확인.
    -   `user1`이 자신이 작성한 게시글의 `title`을 수정하고, `slug`도 함께 변경되었는지 확인.
-   **실패 케이스**
    -   인증 토큰 없이 수정을 시도하고 401 Unauthorized 에러를 받는지 확인.
    -   `user2`의 토큰으로 `user1`이 작성한 게시글 수정을 시도하고 403 Forbidden 에러를 받는지 확인.
    -   존재하지 않는 `slug`로 수정을 시도하고 404 Not Found 에러를 받는지 확인.

## 6. 게시글 삭제 (DELETE /api/articles/{slug})
-   **성공 케이스**
    -   `user1`이 자신이 작성한 게시글을 삭제하고 204 No Content 응답을 받는지 확인.
    -   삭제 후 해당 `slug`로 다시 조회를 시도했을 때 404 Not Found 에러를 받는지 확인.
-   **실패 케이스**
    -   인증 토큰 없이 삭제를 시도하고 401 Unauthorized 에러를 받는지 확인.
    -   `user2`의 토큰으로 `user1`이 작성한 게시글 삭제를 시도하고 403 Forbidden 에러를 받는지 확인.
    -   존재하지 않는 `slug`로 삭제를 시도하고 404 Not Found 에러를 받는지 확인.
