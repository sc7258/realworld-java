# 테스트 시나리오: 태그(Tags) 기능

## 1. 태그 목록 조회 (GET /api/tags)

- **성공 시나리오**
  - **TC1.1**: 여러 게시글에 "java", "spring", "testing" 태그를 각각 추가한 후, `/api/tags`를 호출한다.
    - **결과**: `200 OK`와 함께 `{"tags": ["java", "spring", "testing"]}` 형태의 JSON 응답을 받는다. (순서는 무관)
  - **TC1.2**: 게시글이 하나도 없거나 태그가 없는 상태에서 `/api/tags`를 호출한다.
    - **결과**: `200 OK`와 함께 `{"tags": []}` 형태의 비어있는 배열을 받는다.

---

## 2. 게시글 생성/수정 시 태그 처리

- **성공 시나리오**
  - **TC2.1**: (게시글 생성) `tagList`에 "java", "spring"을 포함하여 새 게시글을 생성한다.
    - **결과**: 생성된 게시글 응답의 `tagList`에 "java", "spring"이 포함되어 있는지 확인한다.
    - **검증**: `Tag` 테이블에 "java", "spring" 레코드가 생성되었는지 확인한다.
  - **TC2.2**: (게시글 수정) 기존 게시글의 `tagList`를 "testing"으로 수정한다.
    - **결과**: 수정된 게시글 응답의 `tagList`가 "testing"으로 변경되었는지 확인한다.
  - **TC2.3**: (기존 태그 재사용) 다른 게시글 생성 시, 이미 존재하는 "java" 태그를 `tagList`에 포함한다.
    - **결과**: 정상적으로 게시글이 생성되고, `Tag` 테이블에 "java" 레코드가 중복 생성되지 않는지 확인한다.

---

## 3. 태그 필터링으로 게시글 목록 조회 (GET /api/articles?tag={tagName})

- **성공 시나리오**
  - **TC3.1**: 게시글 A에는 "java", "spring" 태그를, 게시글 B에는 "java" 태그만 추가한 후, `?tag=spring`으로 조회한다.
    - **결과**: `200 OK`와 함께 게시글 A만 포함된 목록을 받는다.
  - **TC3.2**: `?tag=java`로 조회한다.
    - **결과**: `200 OK`와 함께 게시글 A와 B가 모두 포함된 목록을 받는다.
  - **TC3.3**: 존재하지 않는 태그(`?tag=unknown`)로 조회한다.
    - **결과**: `200 OK`와 함께 비어있는 게시글 목록(`articles: []`)을 받는다.

---

## 4. 게시글 조회 시 태그 확인

- **성공 시나리오**
  - **TC4.1**: (단일 조회) TC2.1에서 생성한 게시글을 단독으로 조회했을 때, 응답의 `tagList`에 "java", "spring"이 포함되어 있는지 확인한다.
  - **TC4.2**: (목록 조회) 전체 게시글 목록을 조회했을 때, 각 게시글 항목에 올바른 `tagList`가 포함되어 있는지 확인한다.
