# 3. 테스트 전략 구체화: 단위 테스트 추가

## 현황
`@SpringBootTest`를 사용하여 컨트롤러부터 데이터베이스까지 모든 계층을 아우르는 통합 테스트(Integration Test) 위주로 작성되어 있습니다.

## 문제점
- **느린 실행 속도**: 전체 스프링 컨텍스트를 로드하므로 테스트 실행에 시간이 오래 걸립니다.
- **테스트의 복잡성**: 특정 로직 하나를 테스트하기 위해 데이터베이스 상태 등 많은 전제조건을 설정해야 합니다.
- **피드백 지연**: 테스트가 실패했을 때 원인이 비즈니스 로직인지, DB 설정인지, 혹은 다른 계층의 문제인지 파악하기 어렵습니다.

## 개선 방안
`CommentService`와 같은 핵심 비즈니스 로직에 대해 **순수 단위 테스트(Unit Test)**를 추가합니다.
- `@ExtendWith(MockitoExtension.class)`를 사용하여 테스트 클래스를 실행합니다.
- `@Mock` 어노테이션으로 Repository와 같이 외부 의존성을 가진 객체를 가짜(Mock) 객체로 만듭니다.
- `@InjectMocks`를 사용하여 테스트 대상 클래스(`CommentService`)에 Mock 객체들을 주입합니다.
- `when(...).thenReturn(...)` 구문을 사용하여 Mock 객체의 행동을 정의하고, 서비스의 로직이 올바르게 동작하는지만을 고립시켜 검증합니다.

## 기대 효과
- **빠른 실행 속도**: 초 단위로 수백 개의 테스트를 실행할 수 있어 빠른 피드백이 가능합니다.
- **명확한 테스트 범위**: 실패 시 원인이 특정 메서드의 로직 문제임이 명확해집니다.
- **설계 개선 유도**: 테스트하기 쉬운 코드를 작성하다 보면 자연스럽게 각 클래스의 책임이 명확해지고 결합도가 낮은 좋은 설계로 이어집니다.
