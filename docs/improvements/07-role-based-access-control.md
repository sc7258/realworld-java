# 07. 역할 기반 접근 제어(RBAC) 도입

## 목표

현재의 "소유권 기반" 권한 모델을 "역할 기반 접근 제어(Role-Based Access Control, RBAC)" 모델로 전환하여, 향후 관리자 기능 등 다양한 사용자 등급별 기능을 확장할 수 있는 기반을 마련한다.

## 현재 시스템의 한계

현재 시스템에서는 사용자를 등록하면 누구나 동일한 권한을 갖는 일반 사용자가 된다. 권한 구분은 오직 "이 리소스의 소유자가 당신인가?"에 의해서만 결정된다.

이 구조는 다음과 같은 한계를 가진다.

-   **관리자 기능 부재**: 다른 사용자의 부적절한 게시물을 삭제하거나, 사용자를 차단하거나, 시스템 통계를 확인하는 등의 관리자 전용 기능을 구현할 수 없다.
-   **확장성 부족**: 향후 "프리미엄 사용자", "에디터" 등 다양한 사용자 등급을 추가하기 어렵다.

## 해결 방안

Spring Security가 제공하는 강력한 RBAC 기능을 도입하여 문제를 해결한다.

1.  **`Role` Enum 생성**:
    -   사용자 역할을 정의하는 `Role` 열거형 클래스를 생성한다. (예: `ROLE_USER`, `ROLE_ADMIN`)
    -   Spring Security의 기본 규칙에 따라 역할 이름은 `ROLE_` 접두사를 사용하는 것을 권장한다.

2.  **`User` 엔티티 수정**:
    -   `User` 엔티티에 `private Role role;` 필드를 추가한다.
    -   데이터베이스에는 역할의 이름(문자열)이 저장되도록 `@Enumerated(EnumType.STRING)` 어노테이션을 사용한다.

3.  **회원가입 로직 수정**:
    -   `UserService`의 `registerUser` 메소드에서 새로운 사용자를 생성할 때, 기본 역할로 `Role.ROLE_USER`를 할당하도록 수정한다.

4.  **관리자 계정 생성 방안 마련**:
    -   최초의 관리자 계정을 생성하기 위한 메커니즘을 구현한다.
        -   **방법 A (추천)**: 애플리케이션 시작 시 특정 프로필(예: `dev`)에서만 실행되는 `CommandLineRunner`를 사용하여, `application.properties`에 정의된 관리자 정보를 바탕으로 계정을 생성하거나 업데이트한다.
        -   **방법 B**: 별도의 관리자 전용 API를 만든다.

5.  **`SecurityConfig` 업데이트**:
    -   `http.authorizeHttpRequests()` 설정에서 특정 경로에 대한 접근 권한을 역할에 따라 제어한다.
    -   예시: `.requestMatchers("/api/admin/**").hasRole("ADMIN")`
    -   Spring Security는 `hasRole("ADMIN")`을 내부적으로 `hasAuthority("ROLE_ADMIN")`으로 변환하므로, `Role` Enum에 `ROLE_` 접두사를 붙이는 것이 중요하다.

6.  **서비스 로직 보강**:
    -   필요에 따라 서비스 계층에서도 현재 사용자의 역할을 확인하여 비즈니스 로직을 분기할 수 있다.

이러한 변경을 통해, 시스템은 단순한 소유권 기반을 넘어 유연하고 확장 가능한 역할 기반의 권한 모델을 갖추게 될 것이다.
